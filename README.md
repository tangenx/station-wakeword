# wakeword — свои слова активации для Яндекс Станции

Станция начинает слушать не только на «Алиса», но и на ваше слово:
«Джарвис», «Компьютер», «Станция» — любое. Слово записывается **микрофонами
самой станции** (после её шумоподавления и эхоподавления), модель обучается
**на самой станции** за пару минут, всё настраивается в браузере.

Прошивка не меняется: демон только слушает звук и просит Алису начать
слушать — через локальный IPC `maind`, как это делает кнопка или приложение.
Штатное «Алиса» продолжает работать.

## Как это устроено

```
микрофоны → maind (AEC, шумодав) ──vqe_0, 16 кГц──▶ wakeword
                                                    │ лог-мел → speech embedding (Google, 96-мерный, каждые 80 мс)
                                                    │ → маленькая сеть вашего слова (обучена на станции)
                                                    └─ слово услышано ──▶ aliced: START_CONVERSATION
```

* **Звук** — подписка на `yio_audio` (`127.0.0.1:9850`), канал `vqe_0`: тот же
  поток, что слушает штатный споттер (без голоса самой станции).
* **Признаки** — фронтенд и speech embedding из openWakeWord, переписанные на
  Go (сверено с ONNX до 1e-3) и сделанные потоковыми; свёртки на NEON. На
  Cortex-A53 это ~10 мс на 80 мс звука; демон со словом занимает ≈16 % одного
  ядра и ~14 МБ памяти.
* **Слово** — классификатор над последними 1,28 с эмбеддингов (≈12 тыс.
  параметров). Обучение: ваши записи × аугментации (скорость, громкость, фон
  комнаты, ваша речь до слова) против фона комнаты, вашей обычной речи и
  готового набора «не-слов» (речь на разных языках, музыка, шум — ~2 ч), с
  упором на самые похожие на слово примеры. Порог подбирается на отложенных
  записях.
* **Срабатывание** — два окна подряд выше порога, затем пауза 2,9 с.
  `START_CONVERSATION` в `aliced`: станция слушает с этого момента (как после
  кнопки), поэтому после слова нужна короткая пауза: «Джарвис… включи свет».

Почему не штатный споттер — [ниже](#почему-не-штатный-споттер).

## Станции

| Станция | Статус |
|---|---|
| Станция 2 | проверено вживую целиком: запись слова, обучение, срабатывание → Алиса отвечает на фразу после слова |
| Мини 3 | проверены звук, обучение на станции (2 мин, ~67 МБ) и запуск Алисы; голосом не проверялось |
| Лайт, Лайт 2, Мини 2, Миди (aarch64, Buildroot, quasar) | должно работать: тот же `maind`, порты берутся из `quasar.cfg` |
| Стрит (32-битное ядро), Макс и Станция 1 (Android), Мини 3 Про (рута нет) | не поддерживаются |

Нужен root (ADB или SSH), см. <https://hackalice.me/start/root/>.

## Установка

### Через YAM

[YAM](https://github.com/nyakokitsu/yam) — пакетный менеджер для станций.
Бинарные пакеты в нём по умолчанию запрещены: в веб-интерфейсе yamd
(`http://<станция>:8099`) включите «Разрешить бинарники» (или
`allow_plugin_binaries = true` в `/data/quazar/yam/data/settings.toml` и
перезапуск yamd). Дальше — загрузите `wakeword-<версия>.yap` там же, в
веб-интерфейсе, либо:

```sh
yam install wakeword-<версия>.yap && yam service enable wakeword
```

Слова хранятся в `/data/wakeword` и переживают переустановку пакета.
Остановить: `yam service disable wakeword`, удалить: `yam rm wakeword`.

### Скриптом (ssh или adb)

```sh
tar -xzf wakeword-<версия>.tar.gz && cd wakeword
STATION_IP=<ip станции> STATION_TRANSPORT=adb ./install.sh
```

Кладёт бинарь и набор данных в `/data/wakeword`, ставит автозапуск
`/etc/init.d/S97wakeword` (единственная правка на rootfs; после OTA её нужно
повторить) и запускает демон. Транспорт выбирается сам: ssh по ключу → ssh по
паролю → adb.

| Переменная | Для чего | По умолчанию |
|---|---|---|
| `STATION_IP` | IP станции (adb, и ssh, если `STATION` не задан) | — (нужен он или `STATION`) |
| `STATION` | ssh-хост: IP или алиас из `~/.ssh/config` | `$STATION_IP` |
| `STATION_TRANSPORT` | зафиксировать `ssh` или `adb` | авто |
| `SSH_KEY` | ключ ssh | ключи и настройки самого ssh |
| `SSH_USER` | пользователь ssh | `root` |
| `STATION_PASS` | пароль ssh (нужен `sshpass`) | — |

Удаление: `STATION_IP=<ip> ./uninstall.sh` (слова остаются) или с `--purge`.

Ставьте **одним** способом: YAM-сервис и init-скрипт вместе запустят два
демона, второй не сможет занять порт.

## Как добавить слово

Откройте `http://<ip станции>:8780` и нажмите «Добавить слово»:

1. **Фон** — 8 секунд тишины в комнате (обычный шум: холодильник, улица, ТВ —
   пусть будет).
2. **Слово** — «Записать», после «Говорите!» один раз произнести слово.
   Минимум 6 удачных записей, лучше 10–15: с разных мест, громче и тише,
   разными членами семьи. Каждую запись можно прослушать и удалить.
3. **Обычная речь** (по желанию) — 20 секунд прочитать текст с экрана: станция
   научится не путать слово с вашей речью.
4. **Обучить** — около 2–3 минут на станции. После этого скажите слово: полоска
   уверенности должна дойти до отметки, а станция — начать слушать.

У каждого слова: включение, чувствительность («реже ↔ чаще»), «Дозаписать»
(добавить записей к старым), «Переобучить». Если станция откликнулась зря,
в «Последних срабатываниях» нажмите «Ложное» — запись станет примером
«не-слова» при следующем обучении.

Короткие и частые в речи слова срабатывают чаще ложно. Лучше всего — 2–4
слога с заметными согласными: «Джарвис», «Компьютер», «Пятница».

## Сборка

```sh
./build.sh                # dist/wakeword (статический aarch64), dist/negatives.bin
./package.sh 0.1.0        # dist/wakeword-0.1.0.yap, dist/wakeword-0.1.0.tar.gz
go test ./...             # фронтенд и embedding против ONNX-эталонов
```

`negatives.bin` (~17 МБ) собирает `tools/build_negatives.py` из
предвычисленных признаков openWakeWord (скачиваются только нужные диапазоны
байт; нужен python3 с numpy). Веса speech embedding лежат в
`internal/kws/assets/oww.bin`; пересобрать их и эталоны тестов —
`tools/export_oww.py` (numpy, onnx, onnxruntime).

GitHub Actions: `ci.yml` на каждый push/PR — gofmt, `go vet` (arm64 и
amd64), тесты на amd64 и на arm64 под qemu (NEON-ядро), сборка бинаря,
staticcheck, shellcheck. `release.yml` по тегу `v*` собирает `.yap` и
`.tar.gz` и публикует релиз; вручную (workflow_dispatch) — только артефакты.

Отладка без станции:

```sh
go build -o wakeword ./cmd/wakeword
./wakeword train -name джарвис -takes takes/ -ambient room.wav -speech talk.wav -negatives dist/negatives.bin -out m.json
./wakeword scan m.json recording.wav      # время и уверенность каждого срабатывания
```

На станции: лог `/tmp/wakeword.log` (init-скрипт) или `yam logs wakeword`;
данные — `/data/wakeword/words/<слово>/` (записи, `model.json`).

`/data/wakeword/settings.json` (правится при остановленном демоне):

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `channel` | канал `yio_audio` | `vqe_0` |
| `gain` | усиление перед всем остальным (`vqe_0` очень тихий) | `32` |
| `dry_run` | только показывать срабатывания, не будить Алису | `false` |
| `words.<id>.enabled`, `.sensitivity` | то же, что переключатель и ползунок в UI | — |

## Почему не штатный споттер

Штатное слово распознаёт споттер `maind` (chen14, Kaldi/TFLite) — до отправки
звука в облако. Исследование показало, что прошивка умеет загрузить свою
TFLite-модель в слот `activation/<слово>`, но только через подменённый
`get_sync_info` (нужен свой прокси на роутере) и только модель в формате
Yandex: потоковая TFLite с их фронтендом (Kaldi fbank, 40 бинов) и
состояниями, которую пришлось бы обучать отдельным ML-конвейером на
компьютере. Плюс такого пути — предзапись: облако
получило бы и слово, и фразу без паузы. Этот проект выбирает путь, который
работает на любой рутованной станции без сети и компьютера.

[openwakeword_features](https://huggingface.co/datasets/davidscripka/openwakeword_features)
